# Live design catalogue

The catalogue is maintainer-only review tooling. It is not copied into plugins
generated by the kit.

Run it at the terminal's native size:

```sh
go run ./cmd/catalogue
```

The catalogue uses the production Bubble Tea shell and the exact geometry
delivered by the terminal. Its six plugin studies are mocks; they establish the
shared UI contract without implementing Recall, Attention Switcher, Session
Switcher, Plugin Configurator, Action Finder, or Debug UI backends.

The live reviewer currently presents three focused, third-round treatments of
the preferred Bento structure: Bento Air, Bento Command, and Bento Flow. They
replace the superseded second-round experiments. The checked-in static matrix
retains the first-round evidence until a live candidate is approved.

Payload-free semantic events are retained under
`$XDG_STATE_HOME/herdr-plugin-kit/catalogue`, or
`~/.local/state/herdr-plugin-kit/catalogue` when `XDG_STATE_HOME` is unset.
They include selected design axes and geometry, never the sample query.

## Controls

| Key | Result |
| --- | --- |
| `d` / `D` | Next / previous design family |
| `e` / `E` | Next / previous component treatment |
| `p` / `P` | Next / previous plugin surface |
| `s` / `S` | Next / previous flow state |
| `t` / `T` | Next / previous built-in theme |
| `f` / `F` | Next / previous named viewport fixture |
| `h` | Toggle the geometry and resize HUD |
| `?` | Open or close the complete navigation guide |
| `/` | Clear and edit the sample query |
| `Enter` | Commit an edit, then advance the compact task flow |
| `Backspace` | Delete one grapheme while editing; otherwise go back one state |
| `Up` / `Down` | Move the visibly marked result selection |
| `Tab`, `Left`, `Right` | Choose an axis and move within it |
| `Esc` | Leave query editing, then quit |
| `q`, `Ctrl-C` | Quit |

The selected fixture is a labelled review target, not a claim that the app can
resize its host terminal. For a one-to-one fixture review, resize the Herdr pane
to the labelled cells and confirm the HUD reports the same delivered geometry.
The `Live terminal` fixture is authoritative during real-device review.

At 18 or fewer rows, each live design uses at most four chrome rows and reserves
six rows for the task. Below `40x10`, the production shell displays Recovery
while preserving the catalogue state. Above `500x200`, it reports the delivered
size and renders a bounded `500x200` projection.

The compact footer always fits within 40 columns and points to `?`. The help
screen uses one row per control group so no instruction depends on clipped
footer text.

## Binding review

Before selecting a binding UI contract, exercise every plugin surface through
its first three flow states and inspect loading, empty, and recoverable-error
states. Compare all three design families and component treatments in at least
one light and one dark theme. Toggle the HUD during a keyboard reopen or other
resize burst and confirm the final reported geometry settles on the newest
size.

Record the chosen Bento treatment, component treatment, theme behavior, and real
device observations in `docs/ui-contract.md`. That file is intentionally not
created until the choice is approved.
